Glosario de la unidad

ACID

Conjunto de propiedades que garantizan la confiabilidad de las transacciones en un sistema de gestión de bases de datos relacional. Comprende Atomicidad (ejecución total o nula), Consistencia (respeto de reglas de integridad), Aislamiento (independencia entre transacciones concurrentes) y Durabilidad (persistencia permanente de los cambios confirmados).

Aislamiento (Isolation Level)

Grado de visibilidad que una transacción tiene sobre los cambios realizados por otras transacciones concurrentes. Se implementa mediante niveles como READ COMMITTED, REPEATABLE READ y SERIALIZABLE, afectando directamente el comportamiento de bloqueos y consistencia.

Autocommit

Modo de operación en el que cada instrucción SQL se confirma automáticamente como una transacción independiente. En programación avanzada suele deshabilitarse para permitir control explícito mediante COMMIT y ROLLBACK.

Bloqueo (Lock)

Mecanismo de control de concurrencia utilizado por el SGBD para garantizar la integridad de los datos cuando múltiples transacciones acceden simultáneamente a los mismos recursos. Puede aplicarse a nivel de fila, página o tabla.

Cursor

Estructura de control utilizada en lenguajes procedurales de bases de datos (PL/SQL, PL/pgSQL, T-SQL) que permite recorrer el conjunto de resultados de una consulta fila por fila para su procesamiento individual.

Deadlock

Situación en la que dos o más transacciones se bloquean mutuamente al esperar recursos retenidos por la otra, impidiendo que cualquiera continúe su ejecución. Los motores de bases de datos implementan detectores automáticos de deadlocks.

Función Definida por el Usuario (User Defined Function – UDF)

Objeto programable que encapsula lógica reutilizable y retorna un valor escalar o un conjunto de resultados. Puede invocarse dentro de consultas SQL, siempre que cumpla restricciones de determinismo y efectos secundarios.

Integridad referencial

Conjunto de reglas que garantizan la coherencia entre tablas relacionadas mediante claves primarias y foráneas.

Lenguaje Procedural (PL)

Extensión del SQL declarativo que incorpora estructuras de control propias de la programación estructurada, tales como variables, ciclos, condiciones y manejo de excepciones. Ejemplos incluyen PL/SQL, PL/pgSQL y T-SQL.

Manejo de excepciones

Mecanismo que permite capturar y controlar errores durante la ejecución de procedimientos almacenados o funciones, evitando fallos abruptos y permitiendo aplicar lógica de recuperación o registro.

MVCC (Multi-Version Concurrency Control)

Modelo de control de concurrencia que permite a múltiples transacciones acceder simultáneamente a los datos mediante el manejo de múltiples versiones de las filas, reduciendo bloqueos de lectura.

Optimización de consultas

Proceso mediante el cual el SGBD analiza y selecciona el plan de ejecución más eficiente para una sentencia SQL, considerando estadísticas, índices y cardinalidad estimada.

Plan de Ejecución

Estrategia interna generada por el optimizador del SGBD para ejecutar una consulta SQL. Define el orden de acceso a tablas, uso de índices y métodos de join, impactando directamente el rendimiento.

Procedimiento almacenado (Stored Procedure)

Objeto programable almacenado dentro del SGBD que encapsula un conjunto de instrucciones SQL y lógica procedural. Permite centralizar reglas de negocio, optimizar rendimiento y mejorar la seguridad al ejecutarse dentro del motor.

Rollback

Operación que revierte los cambios realizados por una transacción no confirmada, restaurando el estado previo de la base de datos.

Transacción

Unidad lógica de trabajo compuesta por una o varias operaciones SQL que deben ejecutarse de forma atómica para mantener la consistencia del sistema.

Trigger

Objeto programable que se ejecuta automáticamente en respuesta a un evento específico (INSERT, UPDATE, DELETE). Puede definirse como BEFORE o AFTER, y operar a nivel de fila o sentencia.

Variables de sesión

Estructuras que almacenan valores temporales durante la ejecución de un bloque procedural dentro de una sesión activa en el SGBD.

Vista (View)

Objeto lógico que representa una consulta almacenada. Puede utilizarse para encapsular lógica compleja o restringir acceso a datos, aunque no ejecuta lógica procedural como un procedimiento almacenado.
